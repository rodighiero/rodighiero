{%- comment -%} Formatted Chicago author-date reference for the "Cite" button, emitted as a hidden 
 and copied to the clipboard (see site-scripts.html). Plain text:
titles are not italicised — the reader can style them after pasting.

Primary contributor is the author, or the editor(s) when there is no author.
There is no third branch for "neither": publication_validator.rb requires one of
the two and aborts the build without them, so a work with no primary contributor
never reaches this file.

The first name is inverted (Family, Given); the rest stay in normal order, with
a serial comma before "and". Formatting branches on the publication type.
{%- endcomment -%}

  {%- assign _people = _item.editor | split: ' and ' -%}
  {%- if _people.size > 1 -%}{%- assign _roleword = ', eds' -%}{%- else -%}{%- assign _roleword = ', ed' -%}{%- endif -%}
{%- endif -%}
{%- comment -%} First contributor is inverted to Family, Given for Chicago style; the
rest join with a serial comma via the same credit-join.html credit-names.html uses. {%- endcomment -%}
{%- assign _first_p = _people | first | strip -%}
{%- assign _words = _first_p | split: ' ' -%}
{%- assign _family = _words | last -%}
{%- capture _given -%}{% for w in _words %}{% unless forloop.last %}{{ w }} {% endunless %}{% endfor %}{%- endcapture -%}
{%- assign _given = _given | strip -%}
{%- capture _first_formatted -%}{{ _family }}{%- if _given != '' -%}, {{ _given }}{%- endif -%}{%- endcapture -%}
{%- comment -%} Splitting on the absent "~~~" sentinel is Liquid's only way to wrap
one string in an array (same convention as credit-names.html), so the inverted first
name can lead the list the rest joins onto. {%- endcomment -%}
{%- assign _rest_people = _people | slice: 1, 9999 -%}
{%- assign _display_people = _first_formatted | split: "~~~" | concat: _rest_people -%}
{%- capture _authors -%}{%- include credit-join.html items=_display_people serial_comma=true -%}{%- endcapture -%}
{%- comment -%} The secondary roles below the author block — editor, translator, interviewer —
are the same list in the same voice three times over, so the split, the Chicago serial-comma
rule and the join live once in credit-role.html rather than being spelled out per role.
Interpolating the front-matter string directly would leave its " and " separators standing
between every name. {%- endcomment -%}

{%- capture _interviewers -%}{%- include credit-role.html raw=_item.interviewer -%}{%- endcapture -%}
{%- assign _t = _item.type -%}
{%- comment -%} What `venue` names is per-type, and publication_types.yml already owns that
question: `container` omitted means venue names the press itself, so it stands in when no
`publisher` is given; any other value means venue names something the work sits inside (a
periodical, a book) and must not be reused as the publisher. Reading the table rather than
re-listing which types are which is what makes a newly added type come out right on arrival —
the reference grammar below is the one place that still knows type names by heart, and it has
to, because Chicago's shapes are not a property of the taxonomy. {%- endcomment -%}
