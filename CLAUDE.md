# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
bundle exec jekyll serve   # local dev server (http://localhost:4000)
bundle exec jekyll build   # build to _site/
```

No test suite, no asset pipeline, no npm for the site itself. The home network view consumes a pre-computed similarity graph and layout — when publications change, re-run `KMP_DUPLICATE_LIB_OK=TRUE python3 scripts/build-network.py` to regenerate `_data/network.json` (committed; the script shells out to Node for the layout step, so Node must be on PATH). See **Network view** below.

## Architecture

This is a Jekyll static site — the personal academic website of Dario Rodighiero at `dariorodighiero.com`.

**Content** lives entirely in `_publications/` as Markdown files, one per publication. Each file's front matter drives everything: `title`, `year`, `venue`, `type` (book / chapter / journal / conference / magazine / interview / map), `author`, `doi`, `thumb` (the single image field — the homepage card + social-preview image; optional `img_border: true` draws a hairline around the card). Optional bibliographic fields enrich the formatted citation (and the homepage search index) without appearing in the visible meta line: `editor`, `translator`, `publisher`, `place`, `volume`, `issue`, `pages`. The `editor`/`translator` byline contributors are joined by `preface` (a preface/foreword author who is not a co-author): it renders in the byline as "Preface by …" (via `byline.html` / `authors-home.html`) and is added to the search index. The `interview` type adds one more byline contributor, `interviewer` (the person who conducted an interview — Chicago cites interviews under the interviewee, so Dario stays the `author` and the interviewer renders as "Interview by …", homepage "interview with / interview by …"); like `preface` it is searchable. Note `venue` is type-dependent (for a book chapter `venue` is the **book title** and the press goes in `publisher`; JSON-LD reads `publisher | default: venue`). The `type` taxonomy is defined once in `_data/publication_types.yml` (label, Schema.org type, DC.type, citation meta tag) — adding a new type means adding one entry there. The `layout: publication` is set globally via `defaults:` in `_config.yml`, so individual files do not declare it.

The body of each file is the abstract. Full-text articles (the complete published text, not just an abstract) put the lead/abstract paragraph first, then a `<!--more-->` marker, then the full text using `##` for section headings. The layout italicizes the part before `<!--more-->` as the lead. Footnotes/references inside full-text articles use kramdown footnote syntax (`[^1]` … `[^1]:`) and follow **Chicago author-date** style (e.g. `Author, First. Year. *Title*. Place: Publisher.`). Figures use `{% include figure.html %}`; **tables** wrap a Markdown table in `<figure class="data-table" markdown="1"> … <figcaption>Table N. …</figcaption> </figure>` (the `markdown="1"` opts the inner table into kramdown parsing, and the `figure`/`figcaption` styling is inherited; column alignment is set per column in the Markdown header, e.g. `|:--|--:|`). Table styling lives in `_layouts/publication.html` under `.body figure.data-table`. The figure width modifiers double up for both images and tables: `narrow` (33%) / `half` (50%) / `three-quarter` (75%) shrink (e.g. `class="data-table half"` shrinks a table to its content width), and `wide` breaks out to ~990px (centered, wider than the 660px text column) — useful for wide many-column tables such as `class="data-table wide"`. `full` is image-only.

**Quotation marks**: use curly quotes (`“ ”`), never caporali/guillemets (`« »`), for Italian and English text. The only exception is French-language quotations, which keep French guillemets.

**CSS** is fully inlined (no external stylesheets, to avoid render-blocking requests): `_includes/main.css` holds the shared foundation (design tokens in `:root` — type scale, line heights, light/dark colors — plus base typography, `.meta-line`, `.authors`, `.cite-ref-btn`, and the mode toggle) and `_includes/nunito.css` the `@font-face` rules; both layouts `{% include %}` them at the top of their page-specific `<style>` block. (`fonts/nunito.css` still exists only for the standalone `404.html`.) JS is inlined in the layouts; shared snippets live in `_includes/common-scripts.html` (mode toggle, cite buttons) and `_includes/head-init.html` (pre-paint color-scheme restore, included in both `<head>`s). No build step:
- `_layouts/home.html` — the only top-level publications page. Three view modes, toggled in the search bar and persisted in `localStorage` under `publicationView`: a **gallery** (custom JS masonry — newest first, packed by shortest column, `GAP_X`/`GAP_Y` in the inline script), a **list** (4-column grid with abstracts), and a **network** (publication similarity graph — see **Network view** below). A single full-width search bar filters across title, authors, editor, translator, venue, publisher, year, type label, volume, issue, pages, DOI and language; in network view it fades non-matching nodes and edges (and links touching them) instead of hiding them. Language is searchable by name (`english`, or `french`/`français`/`francais`, or `italian`/`italiano`) — derived per card from the front-matter `lang` (absent = English) and appended to each card's `data-search` haystack; only distinctive full names are indexed (not the 2-letter ISO codes, which as substrings would match unrelated words). The `.at-top` class is added by JS to suppress the top hairline on first-visible (list) or y=0 (gallery) cards. Author/editor/translator/preface lines come from `_includes/authors-home.html`, which strips "Rodighiero" and prefixes with `with` / `edited with` / `translated with` / `preface with` (or `edited by` / `translated by` / `preface by` when Dario is not in the list). On `<= 1024 px` viewports the layout forces gallery (the toggle is hidden via CSS).
- `_layouts/publication.html` — individual publication pages. Generates a formatted Chicago author-date reference in a hidden `<pre>` (via `citation.html`) and copies it to the clipboard on "Cite" button click. Prev/next navigation is computed in Liquid, sorted by year descending then title descending. Uses `_includes/authors.html` (the full citation, not the homepage shorthand). Above the footer nav it renders a **"Related publications"** list — the page's three closest works, read from its node's `related` array in `site.data.network` (matched by `url`); a non-English suggestion carries a small language tag. See **Network view** for how `related` is computed (and note it works for **every** language, unlike the English-only graph).

**Bio** text lives in `README.md`, split into three paragraphs with `<!-- split -->` comments. `_plugins/readme_content.rb` reads it at each build cycle and exposes it as `site.data.readme_content` for the `home` layout. This way `README.md` doubles as the GitHub repo readme.

**Images** all live under `images/`: `images/@cards/` holds full-size card/social images (many `thumb` values carry the `@cards/` prefix); per-article figures sit in `images/<publication-slug>/` subfolders; `images/@thumbnails/` holds one flat max-800px card thumbnail per publication, named `<slug>.webp` after the publication's .md filename (generated by `scripts/generate-thumbnails.py`, which always re-encodes at thumbnail quality, committed to the repo — rerun it after adding or changing a card image). All source WebPs are stored at libwebp's **method 6** (max compression effort — a quality-neutral setting that just packs the same pixels tighter; see the `-m` note below): run `python3 scripts/optimize-images.py` after adding new images to re-encode every WebP under `images/` (except `@thumbnails/`, which its own generator already writes at method 6, and `@icons/`) at method 6 to a strict visually-lossless PSNR target, keeping the result only when it is meaningfully smaller — so no image is ever degraded or enlarged, and the pass is idempotent. Use `--dry-run` to preview savings. (`method` is cwebp's effort dial `-m` 0–6; it does **not** change quality, so a higher method means a smaller file at the same fidelity — most gains come from figures originally saved with the fast default.) **There is one image field, `thumb`** — a path under `images/` (e.g. `@cards/<Name>.webp`, or a body figure like `<slug>/fig_002.webp` when the card should show a figure from the article). It is the source for the homepage card thumbnail **and** the OG/Twitter/JSON-LD social image (`_social_img = thumb`), so the shared preview always matches the card. There is **no on-page hero**: every publication's on-page imagery comes from body figures (`{% include figure.html %}`). Abstract-only entries whose "content" is really a single image — a book cover, a map, a magazine spread — open the body with a **caption-less lead figure** pointing at that image (usually the same `@cards/<Name>.webp` the `thumb` uses). Because a `thumb` can have any aspect ratio, the homepage card reserves space from the **thumbnail's own** intrinsic size (read at build time via the `image_size` filter); the author portrait sits directly in `images/` (full-size `Dario-Rodighiero.webp` for OG cards/JSON-LD, downsized `Dario-Rodighiero-640.webp` for the homepage header); `images/@icons/` holds the site icon set — `favicon.ico` (legacy tab icon, ~5 KB), the vector `icon.svg` (modern browsers), `apple-touch-icon.png` (180px, iOS/Android home screen), and `icon-192.png` / `icon-512.png` referenced by the root `site.webmanifest`. All are derived from one orthographic graticule-sphere source on a white background; both layouts declare them in `<head>` (SVG preferred, `.ico` as fallback) plus `<link rel="manifest">`. The `@` prefix sorts those folders first in listings; an underscore would not work, since Jekyll excludes underscore-prefixed paths from the build. OG/Twitter cards and JSON-LD use `/images/{{ thumb }}` (with `og:image:width`/`height` read from that image via `image_size`); homepage cards use `/images/@thumbnails/{{ slug }}.webp`.

**Fonts** are self-hosted under `fonts/` (Nunito). **JS** dependencies are self-hosted under `js/` (only D3 v7 today, loaded lazily by the network view). No CDN dependencies.

**Network view** is a publication similarity graph rendered with D3 from `js/d3.v7.min.js` (lazy-loaded on first open). Everything it needs — similarity **and the layout itself** — is pre-computed offline by `scripts/build-network.py`, which: (i) parses Markdown abstracts and strips footnotes, bibliographies, headings, links, inline code, HTML and Liquid tags, blockquote markers, bold/italic emphasis, and every parenthetical aside (citations, figure references, acronyms) together with any leftover list markers; (ii) embeds title + full text with `Alibaba-NLP/gte-base-en-v1.5` (768-dim, 8192-token window via `MAX_SEQ_LENGTH`, long enough that full-text articles are embedded whole rather than truncated) — **English originals natively, non-English originals via machine translation into the same space** (opus-mt; see the per-page suggestions section for details), so every original work has a comparable vector; a **translation** is not embedded (it borrows its source's vector and is attached by the dashed forced edge below); (iii) computes pairwise cosine similarity among all originals; (iv) attaches each translation as a regular node joined **only** to its original by a forced edge — drawn dashed on the page — rather than linked by similarity; (v) shells out to **`scripts/layout-network.js`** (Node + the vendored d3) to bake the force-directed arrangement over all nodes; and (vi) writes `_data/network.json` (committed) — the node list (slug, title, url, index, **baked `x`/`y`**), the **`links`** array (**mutual k-nearest-neighbour** over all originals: a pair (of any language) is linked only when each ranks the other within its top `MUTUAL_K = 2` most-similar neighbours *and* the similarity clears `STRONG_SIM = 0.65` — so every similarity edge is reciprocal and a node may carry several edges; a node whose top picks never reciprocate is then given a single **nearest-neighbour fallback** edge to its strongest match above `FALLBACK_SIM = 0.60` (kept below `STRONG_SIM` so these rescue links form a distinct weaker tier) — flagged `fb` in the link and drawn at reduced opacity on the page, since it is one-directional and weaker than the reciprocal backbone — but a node similar to nothing, or already attached via a translation edge, is left unconnected), the **`canvas`** size the positions were baked into, and a per-node **`related`** array (the three closest works — the single "three closest" list, shared by the publication pages and the network selection panel; see below). The internal similarity matrix is used only at build time (for the mutual-KNN links and the layout) and is deliberately **not** written to `network.json`. A non-English **original** now participates in the similarity graph like any English one (embedded via machine translation), so it carries measured edges — e.g. *Méduse* ↔ *The Trajectories Tool* (0.91); a very strong cross-language pair can pull both nodes into their own small component, which is in keeping with this graph's many small clusters. Only **translations** are excluded from the similarity search: a human translation of an English original (`translation_of` in its front matter) carries the forced dashed edge to its source described above. Every node's **selection panel** lists "three closest" from that same `related` array — the identical list its publication page shows — so the graph and the pages never disagree.

**Per-page "related" suggestions** are a **separate** ranking of the same embeddings, layered on the same file for the publication pages. Each node also gets a **`related`** array — its `RELATED_K = 3` closest publications by cosine similarity in the English embedding space — the single "three closest" list, consumed by both `publication.html` and the network selection panel (so the two never disagree). To place a non-English publication in that space, `build-network.py` **machine-translates** it to English: a non-English **original** (not itself a translation) is translated with a small offline opus-mt model (`Helsinki-NLP/opus-mt-fr-en` / `opus-mt-it-en`, chosen per `lang` from `OPUS_MODELS`; sentence-chunked to the model's window, deterministic beam search) and embedded like any English document; a **translation** simply borrows its source's vector (same work, no MT needed). **Every publication is a candidate, translations included** — only the page itself is excluded — so a translated work's page leads with the same work in the other language at ~1.00 (e.g. *The Analogous City, the Map* → *La Città Analoga, la Mappa*, tagged), and cross-language suggestions surface naturally. Each **work** appears at most once, though: a translation shares its source's vector, so the two tie and the tie breaks toward the original (a translation only fills a slot when its work isn't already listed), which keeps the same work from taking two of the three slots. How this relates to the graph: the same original vectors also build the internal similarity matrix behind the mutual-KNN edges (a non-English original is a first-class similarity node — see above), but that matrix lives only at build time and is not shipped; the browser reads `related` alone. Machine translations are held in a gitignored `scripts/.translation-cache.json` (keyed by model + source text, like the embedding cache), so only originals whose text changed are re-translated; add a language to `OPUS_MODELS` if a new source language appears. `layout-network.js` is the single source of truth for the graph geometry — it owns the link rule (`MUTUAL_K`, `STRONG_SIM`, `FALLBACK_SIM`), the force constants (`NODE_SPACING`, `CHARGE_STRENGTH`, `GRAVITY`, `LINK_DIST_BASE`/`LINK_DIST_SPAN`, `CHARGE_DISTANCE_MAX`, `LAYOUT_SEED`, `LAYOUT_TICKS`), the component-anchoring strategy (`ANCHOR`: `center` — all nodes share one gravity well, so clusters settle as islands and unconnected nodes fill the gaps — or `ring` — largest component centred with the rest pinned on a perimeter ring, which suits one dominant hub but scatters this many-small-components graph into a halo), and the `CANVAS_W`/`CANVAS_H` it lays out into. Note collide spacing (`NODE_SPACING`) governs marker/click separation only, not label legibility: labels render on hover, one at a time. The page consumes the data via Liquid and only **fit-scales** the baked positions into the live stage (uniform scale + center, fixed-px markers/labels; re-fit on resize) and draws the baked links — no force simulation runs in the browser. Re-run `KMP_DUPLICATE_LIB_OK=TRUE python3 scripts/build-network.py` after editing publications (it needs Node on PATH for the layout step).

**Plugins**: `jekyll-feed` (RSS for the `publications` collection), plus six local plugins in `_plugins/`:
- `autolink_urls.rb` — Liquid filter that wraps bare `http(s)://` URLs in anchors when rendering full-text bodies (skips URLs already inside `<a>` tags)
- `decode_numeric_entities.rb` — Liquid filter turning numeric character references (`&#8217;` / `&#x2019;`) into UTF-8 characters; applied to publication excerpts before `escape_once`, which would double-escape hex entities
- `git_mtime.rb` — adds `git_mtime` (last commit date) to each publication and `site.data` for sitemap `lastmod`; needs full git history (the deploy workflow uses `fetch-depth: 0`)
- `image_size.rb` — Liquid filter returning a WebP's intrinsic pixel dimensions (pure-Ruby parser), used by `_includes/figure.html` to set `width`/`height` and avoid CLS
- `publication_date.rb` — derives `page.date` from `year` so the RSS feed preserves the homepage sort order
- `readme_content.rb` — exposes `README.md` as `site.data.readme_content` (see Bio above)

## SEO

Both layouts share a common `<head>` structure:
- `<title>`, `meta description`, `meta keywords`, `rel=canonical`, `robots: index, follow`
- Open Graph (`og:title`, `og:description`, `og:url`, `og:type`, `og:image`, `og:image:alt`, `og:locale`)
- Twitter Card (`twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`)
- JSON-LD structured data

**`og:locale`** is set to `en_US` by default; publications with `lang: it` in their front matter get `it_IT`, and `lang: fr` gets `fr_FR`. The same `lang` (defaulting to `en`) also drives the publication page's `<html lang>`, the `citation_language` / `DC.language` meta tags, and JSON-LD `inLanguage`, so each page declares its real language end-to-end. The homepage stays `en` (English UI/bio); there is no translated UI or per-language page tree.

**OG/Twitter image**: `home.html` always uses the author portrait (`images/Dario-Rodighiero.webp`). `publication.html` uses `page.thumb`, falling back to the same portrait so social cards are never blank.

**JSON-LD types** on publication pages follow Schema.org: `Book`, `ScholarlyArticle` (journals, conferences, book chapters), `Article` (magazine pieces — not peer-reviewed scholarly venues, so they get the more general type), and `Map`. `home.html` emits a `WebSite` + `Person` graph with `sameAs` links to ORCID, Google Scholar, GitHub, LinkedIn, and Zotero.
