{%- comment -%} The portrait is a card's photo, so it is as wide as its column: a fixed 251px at two columns and up, and the whole page at one, which is where the file sizes are decided. A 390px phone shows it at 323 CSS px, so it asks for 646 device pixels at 2x and 968 at 3x — both just past the 640 copy, the 2x case by six pixels — and with only 640 and 1200 to choose from, every modern phone took the 1200 (50KB) for want of anything between. Hence the ladder: 768 (19KB) covers 2x, 1024 (27KB) covers 3x, and the 1200 original — the same file the OG card and the JSON-LD point at — is left for the widest one-column case. Desktop is untouched at 640. All four are one family: cwebp -m 6 -sharp_yuv -q 81, matching the quality the 640 copy was already made at. A ladder only pays if `sizes` is honest, so the column is stated as it is rather than as 100vw: an overstatement is safe with two candidates (it can only bias the choice upward) but with four it costs a rung — 100vw on that same phone asks 780 at 2x and takes the 1024 instead of the 768. 67px is the page's own inset, 2 × body padding + 2 × --card-pad = 48 + 19.2. (100vw itself counts a scrollbar the layout doesn't, which leaves a hair of overstatement — the safe direction.) Every number here is hand-computed from values that live elsewhere: an attribute the preload scanner reads before any stylesheet exists is the one place on this page that cannot say var(--card-w). So they are written out to be greppable when those are retuned — 612px is the two-column threshold, gridWidth(2) + PAGE_PAD = 2 × --card-w + --card-gap + 48; 251px is a card's photo, --card-w − 2 × --card-pad = 270 − 2 × 9.6. Nothing breaks if they drift, which is exactly the risk: the browser just picks the wrong rung, silently. {%- endcomment -%}

How the Network Is Built

A Map of the Publications by Full-Text Similarity

  1. Each file in _publications/ is stripped to plain prose — no footnotes, headings, links, or markup.
  2. Its text becomes a 768-dimension vector via gte-base-en-v1.5; non-English originals are machine-translated first.
  3. Cosine similarity is measured between every pair of embedded papers.
  4. Edges use mutual nearest neighbors (k = 2): each ranks the other in its top two, above 0.65.
  5. A node with no mutual match keeps one faint edge to its closest above 0.60, or none.
  6. A translation stays a node, tied to its original by a dashed forced edge, not by similarity.
  7. A pre-computed D3 force simulation lays out the nodes, so the graph loads already settled.

Hover a node to read its title; click to select it and reveal its closest matches below.
